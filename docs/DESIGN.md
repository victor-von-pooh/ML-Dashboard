# 設計

ML-Dashboard の設計の方針をまとめる.

## 目的

[ML-Found](https://github.com/victor-von-pooh/ML-Found) で行った実験の結果を, ローカルの Web アプリで確かめられるようにする.
TensorBoard に近いが, ML-Found の出力の形を前提にすることで, 学習のコードにログを書く処理を足さなくても, 既にある実験をそのまま一覧にして比べられるようにする.
学習の起動と進み具合の確認, 中断もアプリから行う.

## 役割の分担

| リポジトリ | 役割 |
| --- | --- |
| ML-Found | 学習のライブラリ. 実験の結果をディレクトリに残す. ダッシュボードが読む情報 (実験の状態, 進み具合) を機械で読める形で書き出し, 外からの中断を受け付ける |
| ML-Dashboard | 画面と API. プロジェクトを登録し, 実験を読み込んで見せる. 学習のプロセスを起動して管理する |
| ML_tester | ML-Found のプロジェクトの実例. ダッシュボードの動作確認に使う |

画面, 入力フォーム, 学習のプロセスの管理はダッシュボードで作り, ML-Found には入れない.
ML-Found には, ダッシュボード以外からも使える汎用の仕組みだけを足す.

## 用語

| 用語 | 意味 |
| --- | --- |
| プロジェクト | ML-Found を使うディレクトリ. `configs/default/`, `configs/experiment/`, 学習のスクリプト (`train.py` など) を持つ. ML_tester では各タスクが 1 つのプロジェクト |
| 実験 (run) | 1 回の学習. ML-Found が `<output_dir>/<name>/<日付>/<時刻>/` に作るディレクトリ 1 つに当たる |
| ジョブ | ダッシュボードから起動した学習のプロセス. 終わると 1 つの実験として残る |

## 構成

```
ML-Dashboard/
├── ML-Found/          # submodule
├── backend/           # Python (FastAPI)
│   ├── pyproject.toml
│   ├── src/ml_dashboard/
│   │   ├── api/       # ルーティングとレスポンスの型
│   │   ├── core/      # プロジェクト, 実験とログの読み込み, ジョブ, メモの管理
│   │   ├── app.py     # アプリの組み立てと, ビルド済みの画面の配信
│   │   └── cli.py     # ml-dashboard のコマンド
│   └── tests/
├── frontend/          # TypeScript (React + Vite)
│   ├── package.json
│   ├── e2e/           # 画面の通しのテスト (Playwright)
│   └── src/
│       ├── api/       # API の型 (OpenAPI から生成) と呼び出し
│       ├── components/
│       ├── features/  # 画面ごとのまとまり
│       └── lib/
├── demo/              # 動作の確認と通しのテストに使う ML-Found のプロジェクト
├── docs/
├── Makefile           # よく使うコマンド
└── .github/workflows/ # lint, 型検査, テスト, 通しのテスト
```

- バックエンドは Python にする. 学習の起動と config の検証に ML-Found をそのまま使えるため
- フロントエンドは TypeScript にする. API の型は, バックエンドが出す OpenAPI の仕様から生成して共有する
- 使うときは 1 つのコマンドで起動し, バックエンドがビルド済みの画面も配信する. 開発時は Vite の開発サーバーから API に転送する

### 主な技術

| 用途 | 技術 |
| --- | --- |
| API | FastAPI, Pydantic, Uvicorn |
| Python の環境 | uv, Ruff, mypy, pytest |
| 画面 | React, TypeScript, Vite, React Router, TanStack Query |
| グラフ | Apache ECharts (拡大, 範囲の選択, 多くの点に強い) |
| 見た目 | Tailwind CSS, ライトとダークの両方 |
| 画面の検査 | oxlint, Prettier, Vitest, Playwright, TypeScript 5.9 (型の生成の道具が対応している版) |

どれも商用利用できるライセンス (MIT, Apache 2.0, BSD) のもの.

## 実験の読み込み

ML-Found の今の出力から, 次のように読み取る.

| 情報 | 読むもの |
| --- | --- |
| 指標の推移 | `history.csv` (列 `epoch`, `train/*`, `valid/*`, `lr`. ML-Found の `trainer.eval_train: true` では, 学習用データを推論モードで評価し直した `train_eval/*` も). 学習中や失敗した実験は `train.log` のエポックごとの指標から作る. `lr_steps.csv` があれば, 更新ごとの学習率も読む |
| config | `config.yaml` (全体), `diff.yaml` (default との差分) |
| ログ | `train.log` (警告とエラーを行ごとに区別) |
| 画像 | 実験のディレクトリの中の画像 (学習曲線, 生成画像など) |
| 未コミットの変更 | `git_diff.patch` |
| 状態 | `run.json` の状態 (実行中のまま残ってプロセスが無ければ不明). `run.json` が無い古い実験は, `train.log` の「学習完了」とエラーの行から判定 |
| 進み具合 | `progress.json` (学習中の実験だけ) |

ML-Found が書く `run.json` (下の「ML-Found に加えたもの」) がある実験では, 状態, ベストのエポック, 環境の情報をそこから読む.
無い古い実験でも, 上の表の情報で見られるようにする.

プロジェクトの実験は, `configs/default/` と `configs/experiment/` の config の `experiment.output_dir` の下を探して見つける.

## 学習の起動

- プロジェクトの学習のスクリプトを, プロジェクトの Python で `--experiment <config>` を付けて別のプロセスとして起動する
    - ML-Found のプロジェクトは `train.py --experiment` の形で動かす前提で作られているため
    - ダッシュボードとプロジェクトで Python の環境を分けられる
- 画面で config を書き換えた場合は, ダッシュボードのデータの置き場に config を書き出して渡す. プロジェクトのファイルは変更しない
- 起動の前に, ML-Found の `load_config` で config の誤りを確かめる
    - 確認の結果は, 誤り (起動できない), 注意 (学習のスクリプトが補えば起動できるもの, 学習率が下がりきらないなど), お知らせ (ML-Found が学習を始めるときに補う値など) に分ける
- 1 つのプロジェクトに学習のスクリプトが複数あり, それぞれ別の default の config を使う場合は, スクリプトの本文に書かれた `configs/default/<名前>.yaml` (1 種類だけの場合) を使い, 無ければ名前で選ぶ (`train_<名前>.py` は `configs/default/<名前>.yaml`, 次に `train_<名前>.yaml`, どちらも無ければ `train.yaml`). 本文はパスの文字を探すだけで, 実行はしない. 実験の出力先も, 全ての default の config から集める
- 中断は ML-Found の「中断の要求」(`STOP`) で行う. エポックの区切りで止めるか, `now` でエポックの途中で止める. 利用者が「すぐに止める」を選んだ場合と, 実験のディレクトリがまだ無い場合だけ, プロセスにシグナルを送る (押すたびに SIGINT, SIGTERM, SIGKILL の順に強くする)

## ML-Found に加えたもの

ML-Found の TODO の項目 3 (進捗を渡す仕組みと学習の中断) のうち, ダッシュボードが使う次のものを加えた (Python のコードから指標を受け取るコールバックは残っている).

| 加えたもの | 内容 |
| --- | --- |
| `run.json` | 実験の状態 (`running`, `completed`, `stopped`, `failed`), 開始と終了の時刻, 予定と実際のエポック数, 監視する指標, ベストのエポックと値, 乱数シード, デバイス, git と環境の情報. 開始時に作り, エポックごとと終了時に更新 |
| `progress.json` | 今のフェーズ (`train`, `train_eval`, `valid`. `train_eval` の間は, そのエポックの学習を終えたものとして進み具合を求める), エポック, バッチの位置と総数, 経過時間. 一定の間隔で上書き |
| 中断の要求 | 実験のディレクトリに `STOP` というファイルがあれば, 今のエポックの区切りで学習を止め, `last.pt` を保存して `stopped` で終える. 中身が `now` ならエポックの途中でも止め, 途中のエポックを捨てて最後に終えたエポックの状態に戻す |

どれもファイルでやり取りするので, ダッシュボード以外 (別の端末のスクリプトなど) からも使える.

## 画面

1. **プロジェクト**: 登録したプロジェクトの一覧. 実験の数, 最新の実験. 実行中のジョブの数は上部のナビゲーションに出す
2. **実験の一覧**: 1 つのプロジェクトの実験の表. 名前, 日時, 状態, 学習時間, ベストの指標, config の主な差分. 並べ替え, 絞り込み, 複数を選んで比べる
3. **実験の詳細**
    - 概要: 状態, ベストのエポックと指標, 学習時間, 乱数シード, デバイス
    - 学習曲線: 指標ごとのグラフ. 学習用と検証用 (と, 学習用データを評価し直した `train_eval/`) を重ね, ベストのエポックと Early Stopping の位置を示す
    - config: 全体と default との差分
    - モデル: モデルの構造, Optimizer, Scheduler (`train.log` から)
    - 環境: git の情報と未コミットの変更, OS, PyTorch, パッケージ
    - ログ: `train.log`. 警告とエラーを強調
    - 画像: 番号の付いた画像のエポックごとの推移 (スライダーと再生), 実験のディレクトリの画像とファイルの一覧
    - メモ, タグ, 星 (ダッシュボードのデータの置き場に保存)
4. **比較**: 選んだ実験の曲線を重ね, config の違う項目とベストの指標を並べる. 2 つ以上の実験にある番号付きの画像の並びは, 同じ番号の画像を横に並べる
5. **ハイパーパラメータの分析**: 同じ名前の実験で値を変えた config の項目と, ベストや最後の指標の関係 (散布図, 値ごとの表, 結果を大きく動かした項目の順位)
6. **学習の起動**: スクリプトと config を選び, フォーム (ML-Found の登録簿の説明と範囲付き) か YAML で書き換え, ML-Found で確かめてから起動する (名前, 必須の引数, 範囲に加えて, 仮のパラメータで Optimizer と Scheduler を作れるか). 値の誤りはフォームに表示する
7. **ジョブ**: 実行中のジョブの進み具合 (エポックとバッチの進捗バー, 残り時間の目安), 中断, 終わったジョブから実験の詳細へ移る

## 段階

| 段階 | 内容 |
| --- | --- |
| 0 | リポジトリの構成, 開発の道具, CI, この設計 (済み) |
| 1 | 見るだけの機能. プロジェクトの登録, 実験の一覧と詳細, 比較 (済み) |
| 2 | ML-Found に `run.json`, `progress.json`, 中断の要求を加える. ダッシュボードから学習を起動し, 進み具合を見て, 止める (済み) |
| 3 | 画面を豊かにする. 実験のメモとタグ (済み), ハイパーパラメータと指標の関係のグラフ (済み), 生成画像のエポックごとの表示と実験の間の比較 (済み), config の入力フォーム (ML-Found の登録簿と合わせる, 済み) |

どの段階も済み. その後に, プロジェクトのまとめての登録, スクリプトごとの default の config, 学習率の更新ごとの表示, エポックの途中での中断などを加えた. 次の段階は決まっていない.

## データの置き場

ダッシュボード自身のデータ (登録したプロジェクト, 起動したジョブの記録, 書き換えた config) は, ユーザーのホームディレクトリの下の 1 か所にまとめ, 環境変数で変えられるようにする.
プロジェクトのディレクトリには, ML-Found が書くもの以外を置かない.

## セキュリティ

ローカルの 1 人で使う前提で, `127.0.0.1` だけで待ち受ける.
ファイルを返す API は, 登録したプロジェクトの実験のディレクトリの中だけを読めるようにし, パスの外への移動を拒否する.

## テスト

- バックエンド: pytest で API と ML-Found の出力の読み込みを確かめる (一時ディレクトリに ML-Found の出力の形を作る)
- 画面: Vitest で表示に使う計算 (YAML の書き換え, 画像の並びなど) を確かめる
- 通し: Playwright で, `demo/` の実験を実際に学習してからダッシュボードを起動し, 一覧, 詳細, 比較, フォームでの起動から完了までを操作する. 同時に届く要求で初めて ML-Found を読み込む場合など, 単体のテストでは出ない不具合を拾う
